## Manual alpha setup (once the authorized CI release provides signed artifacts)

Use only a maintainer-approved, production-signed ARM64 alpha APK and the matching alpha desktop package. The development and synthetic-signature test artifacts above are not release-upgrade candidates.

1. Verify the published source revision, version, SHA-256 checksum and Android signing-certificate digest before installation. Back up the test folders, KDBX, and any existing app data; do not clear application storage to work around a failed upgrade.
2. Android: install the verified APK with the system package installer or `adb -s <your-device-serial> install -r <verified-alpha.apk>`. Verify the installed version. Test a fresh installation only on a separate disposable device/profile; never uninstall the existing app to force an incompatible signature.
3. Linux: install the verified alpha deb using the platform package manager or run the verified AppImage on a supported host; use an isolated test account/profile for local-reset checks. Confirm the OS credential store is available and that the local Syncthing peer uses a disposable folder.
4. Record artifact version, SHA-256, source revision, device model/OS, WebView version and each outcome. Use a test folder/database and backup before testing an in-place upgrade.

## Manual alpha checklist


- [ ] Fresh Android install: name-only onboarding, no PIM tab, settings accessible on each tab.
- [ ] In-place upgrade with same release signature: existing vault, peer list, saved folder credentials and favorites retained; no clearing of app data.
- [ ] Linux package startup and pairing with Android; approved peer shows authenticated connection. Verify wrong password and declined peer remain locked/unapproved.
- [ ] Browse several large folders, filter/sort, move between paths, unlock a locked folder via its row; no freeze or disconnect. Export logs if slow.
- [ ] Open Local enters the correct folder in Android Files; open a synthetic KDBX via the system picker and edit from Android and Linux. Confirm both directions and offline edit convergence; retain conflicts.
- [ ] Mark a test file favorite; edit from an external app with Syncpeer closed and background sync enabled. Test balanced and battery-saving policies; verify resume after allowed conditions return and opt-out behavior.
- [ ] Restart app/phone; verify saved peer settings, document access, recovery and recent diagnostic logs. Export a disposable Personal Space backup and verify import over existing local data is safely refused. Migration is deferred to 0.7.1.
- [ ] Review known limitations: OS-managed battery restrictions, remote-only SAF entries not exposed yet, PIM hidden, conflicts not automatically merged, initialized-vault backup import deferred.
- [ ] Maintainer accepts alpha or reports issues for alpha.2; no rc.1 until acceptance.

Sustained transfers, real NAT/relay and mobility, OEM power management, extended interoperability, hardware power loss and store review belong to the subsequent RC field evidence. Emulated process death is not proof of physical power loss.
